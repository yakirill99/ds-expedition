# Инструкции для AI-агентов: ds-expedition

## Язык

- **Всё проектное общение, комментарии, docstrings, README и документация — на русском языке.**
- Исключение: технические термины, названия библиотек, классов/функций, переменных, конфигов — как принято в Python-сообществе (английский snake_case / CamelCase).
- Не переводи названия методов ML и метрик дословно; используй устоявшиеся термины: `train_test_split`, `cross_val_score`, `roc_auc`, `precision`, `recall`.

## Контекст проекта

- Хакатон «Экспедиция. Data Science», КОЗ №3 «Комплексирование».
- Команда из 5 человек, модульная разработка, DevOps-подход.
- Python-репозиторий с `uv`, `ruff`, `pytest`, `pre-commit`, CI через GitHub Actions.

## Стек и инструменты

- Управление зависимостями: `uv` (`pyproject.toml`, `uv.lock` коммитится).
- Линтер/форматтер: `ruff`.
- Тесты: `pytest`, структура зеркально `src/expds/`.
- Запуск задач: `Makefile` (`make setup`, `make test`, `make lint`, `make train`, `make submit`).
- Данные и веса **не коммитятся**. Пути фиксируются в `configs/`.
- Логирование экспериментов: MLflow / W&B (фиксируй `seed`, git-коммит, метрики).

## Структура модулей (`src/expds/`)

| Модуль | Ответственность |
|---|---|
| `data` | загрузка, чтение, валидация данных |
| `features` | препроцессинг, генерация признаков |
| `models` | модели по отдельным источникам |
| `fusion` | комплексирование (объединение моделей/источников) |
| `evaluation` | метрики, валидация, формирование сабмита |

- Каждый модуль имеет чёткий интерфейс (входы/выходы). Изменения интерфейсов согласовывай с владельцем модуля.
- Перед реализацией новой фичи проверь `docs/REPO_SETUP.md` и README соответствующего модуля.

## Правила работы с кодом

- Пиши чистый, читаемый код. Документируй нетривиальные решения на русском.
- Функции и классы — на английском в `snake_case` / `CamelCase`.
- Комментарии и docstrings — **на русском**.
- Не коммить большие файлы (>5 МБ), ноутбуки с выводами, временные артефакты.
- Используй `pre-commit` перед коммитом.

## Ветки и PR

- `main` ← `develop` ← `feature/<модуль>-<задача>` или `exp/<автор>-<идея>`.
- Создавай фичу от `develop`, живи 1–2 дня, мержи через PR.
- Теги сабмитов: `v0.1-baseline`, `v0.2-lb0.83`.

## Как проверить изменения

```bash
make lint      # ruff check + format --check
make test      # pytest
make train     # локальный запуск обучения
make submit    # формирование сабмита
```

## Чего избегать

- Не добавляй новые зависимости без явной необходимости; если добавляешь — фиксируй через `uv add`.
- Не меняй структуру `src/expds/` без согласования с командой.
- Не пиши код без тестов для критичных путей.
