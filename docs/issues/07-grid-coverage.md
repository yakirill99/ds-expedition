# Патч-отчёт: аудит покрытия сеток разметкой

Коммит: `scripts/grid_coverage_check.py` (новый файл, без изменений библиотеки).
Ветка: `test/geo-pr55`.

## Зачем

Oracle-sweep от 2026-11-11 (configs/night3.yaml, 12 val-участков, GT 1518)
показал f1 0.785 при r 0.696, и **456 из 461 FN — причина «вне сетки»**:

| Участок | GT | вне сетки | f1 |
|---|---|---|---|
| 036_Тимерево | 885 | 312 | 0.745 |
| 066_Московиты | 69 | 67 | 0.047 |
| 008_Герите | 45 | 36 | 0.286 |
| 102_Гнёздово_Заольшанская | 136 | 20 | 0.921 |
| 056_Фалхан | 53 | 17 | 0.673 |

Пост-обработка при этом чистая: на реальном фото-участке `130_Курганы_1`
(Яндекс.Диск, сырой tif → build_site_rasters → GT через detect-цепочку)
оракул даёт **f1 = 1.000** (33/33, 0 FP; NMS корректно дожимает 66 → 33).
Значит, потолок оракула упирается не в post, а в сетки участков: bbox
разметки шире bbox растровых данных (или CRS/сдвиг — см. Δx/Δy в выводе).

## Что делает скрипт

`scripts/grid_coverage_check.py`:
- сетка участка: `samples/sample_meta.json`, иначе первый tif из `layers/`;
- разметка `labels.geojson` репроецируется из `labels_crs` (обычно
  EPSG:3857) в CRS сетки (pyproj);
- каждый полигон классифицируется: целиком вне / частично / внутри;
- для проблемных участков печатает Δx/Δy bbox разметки относительно bbox
  сетки (систематический сдвиг виден сразу) и рекомендуемую сетку
  `Grid(...)` покрывающую объединение данных и разметки (в Мпкс, чтобы
  поймать вырожденные случаи);
- torch не нужен: только yaml + pyproj + json.

## Проверено

- `ruff check scripts/grid_coverage_check.py` — чисто.
- На реальных данных `130_Курганы_1` (Яндекс.Диск): GT 33, вне сетки 0 —
  согласовалось с `oracle_diag.py` f1 1.000 на том же участке.
- Тесты ветки `tests/test_oracle.py tests/test_post.py tests/test_augment.py`
  — 65 passed.

## Как пользоваться

```bash
uv run python scripts/grid_coverage_check.py --config configs/night3.yaml
uv run python scripts/grid_coverage_check.py --sites-dir data/rebuilt \
    --sites 036_Тимерево,066_Московиты,008_Герите
```

Дальше: участки с «вне > 0» пересобрать так, чтобы сетка покрывала
разметку (пересборка из полных сырых данных), и повторить
`scripts/oracle_diag.py --config configs/night3.yaml --sweep`.
Цель — «вне сетки 0» и oracle f1 ≥ 0.95 до ретрейна.
