# Формат хранения локации для визуализации

Документ описывает соглашение по подготовке данных одной локации (участка карты)
для загрузки в веб-приложение `viz`.

## Структура папки

```text
data/
└── <location-dir>/
    ├── manifest.json          # метаданные локации
    ├── README.md              # описание от владельца данных
    ├── raw/                   # исходные данные (не для отображения напрямую)
    │   ├── lidar_points/
    │   ├── lidar_rasters/
    │   ├── aerial/
    │   └── annotations/
    └── tiles/                 # готовые тайлы для Leaflet
        ├── satellite/
        │   └── {z}/{x}/{y}.png
        ├── lidar/
        │   └── {z}/{x}/{y}.png
        └── aerial/
            └── {z}/{x}/{y}.png
```

## `manifest.json`

Обязательные поля отмечены `*`.

```json
{
  "slug": "001-gnezdovo-nivlenskoe",
  "name": "001 Гнёздово Нивленское",
  "utm": "36N",
  "crs": "EPSG:32636",
  "center": {
    "lat": 55.1234,
    "lon": 36.5678
  },
  "zoom": 15,
  "bounds": {
    "west": 36.55,
    "south": 55.11,
    "east": 36.59,
    "north": 55.14
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `slug`* | string | Уникальный код локации (ASCII, без пробелов). Используется в URL. |
| `name`* | string | Человекочитаемое название. |
| `utm` | string | UTM-зона (например, `36N`). |
| `crs` | string | Система координат (например, `EPSG:32636`). |
| `center`* | object | Центр карты `{lat, lon}` в WGS84. |
| `zoom`* | integer | Начальный масштаб Leaflet (обычно 10–18). |
| `bounds` | object | Границы покрытия в WGS84: `west`, `south`, `east`, `north`. |

## Папки слоёв (`tiles/`)

Каждая подпапка внутри `tiles/` становится отдельным переключаемым слоём в UI.
Имя папки — это `slug` слоя (ASCII, без пробелов), который попадёт в URL:

```text
/viz/tiles/<location_slug>/<layer_slug>/<z>/<x>/<y>.png
```

Рекомендуемые имена слоёв:

| Слой | Описание | Источник |
|---|---|---|
| `satellite` | Спутниковый снимок | `01_..._La_точки` → растр интенсивности/DSM |
| `lidar` | Карта высот или интенсивности LiDAR | `02_..._Li_карты` |
| `aerial` | Аэрофотосъёмка | `03_..._Ae_немецкая` |
| `annotation` | Разметка/маска | `06_..._разметка` |

## Преобразование исходных данных

### 1. Точки LiDAR (`*_La_точки`)

Сырые `.las`/`.laz` нельзя показать на карте напрямую. Варианты:
- Сгенерировать растр высот (DSM/DTM) → слой `lidar`.
- Сгенерировать растр интенсивности → слой `satellite`.

### 2. Растры (`*_Li_карты`, `*_Ae_немецкая`)

Если данные уже в формате GeoTIFF, нарежьте их в тайлы:

```bash
# Через GDAL (рекомендуется)
gdal2tiles.py --xyz --zoom=10-18 input.tif tiles/<location>/<layer>/

# Через скрипт проекта
uv run python scripts/tilize_geotiff.py \
    --input data/.../input.tif \
    --output tiles/<location>/<layer>/ \
    --zooms 10 11 12 13 14 15
```

### 3. Разметка (`*_разметка`)

- Векторная разметка → GeoJSON + отображение поверх слоя.
- Растровая маска → тайлы в папку `tiles/<location>/annotation/`.

## Импорт в приложение

```bash
uv run python web/manage.py import_location \
    --tiles-dir tiles \
    --slug 001-gnezdovo-nivlenskoe
```

Если в исходной папке есть `manifest.json`, координаты центра и название
подтянутся автоматически.
